# 서버 계약

- 서버는 `Idempotency-Key`로 중복을 제거해야 합니다. 같은 키와 같은 payload의 재전송은 동일 거래로 처리합니다.
- 200/201은 기록 완료입니다. 이미 기록한 키를 재전송해도 기록 완료 응답을 반환합니다. 클라이언트는 204도 성공으로 분류합니다.
- 202는 접수했지만 아직 확정되지 않았다는 뜻입니다. 클라이언트는 항목을 보관하고 이후 flush에서 다시 확인합니다.
- 409는 같은 키에 다른 payload를 보낸 경우입니다. 클라이언트 버그로 보고 영구 거절하며 키를 포함한 Error 로그를 정확히 한 줄 남깁니다.
- 422는 잘못된 영수증이며 영구 거절합니다. 400/401/403/404도 영구 거절입니다.
- 408/429/500/502/503/504 및 정규화된 전송 오류·시도 타임아웃은 재시도합니다. 그 외 미지정 상태와 예상 밖 예외는 StopKeep입니다.
- Retry-After는 429/503에서만 초 또는 HTTP-date로 해석합니다. 서버의 예약 값은 MaxDelay로 자르지 않습니다. 인라인 한도를 넘으면 outbox에서 기다립니다.

이 계약은 서버 구현을 포함하지 않습니다. 안전한 중복 처리는 서버가 이 계약을 지킬 때 성립합니다. 로그에 영수증이나 서명 원문을 포함하지 않습니다.
